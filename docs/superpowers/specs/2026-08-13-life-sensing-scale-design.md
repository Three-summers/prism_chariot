# 生命感知页面等比缩放与视觉协调设计

## 背景

当前生命感知页面以 `1600x900` 为设计尺寸，主要样式尺寸使用 `px`。现有 `useUiScale` 只修改 HTML 根字号，而页面没有使用 `rem`，因此窗口变大时页面仍保持左上角的 `1600x900` 尺寸。`.app-shell` 预留了 `transform: scale(var(--ui-scale))`，但该变量没有根据窗口尺寸更新，且用于居中的 `.stage` 没有渲染到页面。

Chrome 实测结果：

- `1600x900` 下右侧“结案处理”内容超出面板，底部操作按钮被裁切。
- `1920x1080` 下页面仍为左上角 `1600x900`，右侧和底部出现大块空白。
- 中间实时画面留白较大，告警条贴近底部；左侧地图网格亮度偏高，抢占视觉注意力。

## 目标

1. 以 `1600x900` 作为唯一设计基准。
2. 在普通窗口、浏览器全屏和不同宽高比下，整个页面完整、居中、等比例缩放。
3. 不拉伸、不裁切；窗口宽高比与设计稿不一致时允许上下或左右留边。
4. 修正结案面板的溢出问题，并协调面板间距、层级和视觉重心。
5. 保留现有深色工业风、业务字段、模块导航和交互行为。

## 方案

### 固定设计画布

新增全屏 `.stage` 舞台，负责占满视口、隐藏溢出并居中放置固定尺寸的 `.app-shell`。`.app-shell` 继续使用 `1600px` x `900px`，不把现有数百处 `px` 尺寸迁移为 `rem`。

缩放倍率由纯函数计算：

```text
scale = min(viewportWidth / 1600, viewportHeight / 900)
```

将结果写入 `--ui-scale`，由 `.app-shell` 使用 `transform: scale(var(--ui-scale))`。变换原点为中心，因此页面在两个方向上都保持居中。

Hook 监听 `resize` 和 `fullscreenchange`，首次挂载时立即计算；卸载时移除监听并恢复原始 CSS 变量。根字号不再由页面 Hook 改写。

### 视觉协调

- 统一标题栏、面板边界、内边距和列间距，减少不同区域的密度跳变。
- 调整右侧结案面板的内部高度分配和底部操作区，保证表单及操作按钮在设计尺寸内完整显示。
- 重新平衡实时画面的上下留白，使 LIVE 占位、告警条和 CASE 表格形成稳定垂直节奏。
- 降低地图网格的背景亮度，保留路线、车辆和当前区域的高亮状态。
- 强化状态数字、异常状态和事件等级的层级关系，但不改变字段内容或业务颜色语义。

## 数据流与边界

```text
窗口尺寸 / 全屏事件
        |
        v
computeUiScale(viewport, 1600x900)
        |
        v
document.documentElement --ui-scale
        |
        v
.stage 居中 + .app-shell transform 缩放
```

缩放只作用于页面视觉画布，不改变 React 业务状态、表单值、导航状态或 SVG 的内部坐标系。所有现有交互继续通过缩放后的 DOM 接收输入。

## 测试与验证

### 自动化测试

为缩放计算添加纯函数测试，覆盖：

- `1600x900` 返回 `1`。
- `1920x1080` 返回 `1.2`。
- `2560x1440` 返回 `1.6`。
- `1920x1200` 返回 `1.2`，证明会取宽高比例中的较小值并避免裁切。
- 小于设计尺寸的窗口按较小方向缩小。
- 非法或零尺寸输入使用稳定的非负结果，不产生 `NaN` 或无穷值。

### 浏览器验证

使用 Chrome DevTools 检查 `1600x900`、`1920x1080`、`2560x1440` 和非 16:9 视口：

- `.app-shell` 的实际视觉边界等比变化并保持居中。
- 页面无横向或纵向裁切。
- 结案面板底部按钮完整可见。
- 无控制台错误，导航、楼层切换、CASE 选择和照片上传入口仍可操作。

## 非目标与风险

- 不迁移整套样式到 `rem`，避免扩大改动范围。
- 不重做生命感知页面的信息架构，不新增业务数据或后端接口。
- `transform` 会改变视觉坐标而不改变布局坐标；若后续接入依赖绝对像素坐标的外部浮层，需要复用同一舞台缩放上下文。
- 页面在极端窄屏下会整体缩小，保证完整显示优先于维持最小字号。
