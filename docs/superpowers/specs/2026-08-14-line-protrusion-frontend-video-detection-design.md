# 配线突出纯前端视频检测设计

## 背景

线突出识别模块目前使用 Mock Dashboard 数据。参考程序位于 `docs/reference_program/配线突出识别`，核心算法以两根导线各自的左、中、右三个光斑为基准，逐帧追踪光斑并计算中间光斑相对左右端点基线的垂直偏移。参考视频 `外寄Part1_1_.mp4` 仅作为本地验证素材，不加入应用资源或本次提交。

## 目标

1. 全部能力在浏览器 TypeScript 中实现，不使用 Python、OpenCV.js、HTTP、WebSocket、CLI、Tauri 或后端进程。
2. 在线突出识别页面选择本地视频，并分别为导线 1、导线 2 水平拖线完成三光斑标定。
3. 视频播放期间逐帧追踪六个光斑，实时显示两根导线的偏移值、状态、基线和光斑位置。
4. 默认预警阈值为 `2°`、报警阈值为 `5°`、灵敏度为 `1×`，三项均可在页面控制条配置。
5. 只在导线状态从正常进入预警或报警时新增 CASE；持续异常不重复新增，恢复正常后再次异常可创建新 CASE。
6. 保持现有生命感知三栏布局、面板顺序、主题系统和 1600×900 等比例缩放。

## 非目标

- 不自动猜测两根导线的完整标定位置；参考视频中存在强反光，用户画线标定更可靠。
- 不提供摄像头采集、CSV 导出或视频进度拖动。
- 不把参考 MP4 复制到 `public` 或提交到 Git。
- 不调整其他模块的布局或数据来源。

## 方案选择

采用原生 Canvas 和 TypedArray 移植参考算法。相比 OpenCV.js，该方案无额外运行时下载和大体积依赖；相比全自动光斑发现，手动画线能避开参考视频中的非目标强反光，并与参考程序行为一致。

## 算法与类型边界

标定以图片归一化坐标保存，每根导线包含三个点：

```ts
interface WireSpot { x: number; y: number }

interface WireCalibration {
  wire: 0 | 1
  spots: [WireSpot, WireSpot, WireSpot]
}

interface LineProtrusionDetectionResult {
  width: number
  height: number
  wires: Array<{
    wire: 0 | 1
    spots: [WireSpot, WireSpot, WireSpot]
    deviationDeg: number
    state: 'ok' | 'warning' | 'alarm'
  }>
  state: 'ok' | 'warning' | 'alarm' | 'failed'
  error?: string
}
```

标定时，算法在用户水平拖线的 `Y ± 12px` 范围内累加灰度亮度，把 X 范围分为三段，在每段最亮列附近 `±4px` 计算亮度加权质心，得到左、中、右三个光斑。拖线长度少于 `20px` 或任一段没有有效亮度时标定失败，并保留上一份有效标定。

追踪时先把帧缩放到最大宽度 `600px`。每个标定点在 `±50px` 搜索窗口中取最大亮度的 `50%` 为阈值，对阈值以上像素做亮度加权质心。左右端点的 Y 固定为标定基线，仅中间点的 Y 参与偏移。每根导线的结果为：

```text
偏移角度 = (
  当前中点 Y - 当前左右端点平均 Y
  - 标定中点 Y + 标定左右端点平均 Y
) × 灵敏度
```

绝对偏移 `< 2°` 为正常，`2°–5°` 为预警，`≥ 5°` 为报警；配置改变后使用当前阈值重新分类。报警优先于预警，任一导线报警时总状态为报警。

## 浏览器视频与交互

线突出页面的中心控制条包含：选择视频、标定导线 1、标定导线 2、开始/暂停、停止、预警阈值、报警阈值和灵敏度。选择新视频后创建 Object URL，加载首帧并进入待标定状态。只有至少一根导线标定成功后才能开始检测；未标定的另一根导线不参与状态计算。

画面使用原生 `<video>` 显示，叠加一个与视频内容区域一致的交互层。标定模式中鼠标按下、移动和释放形成水平拖线，指针坐标转换为源视频坐标后读取当前 Canvas 帧。检测循环优先使用 `requestVideoFrameCallback`，不可用时使用 `requestAnimationFrame`，每个已呈现视频帧最多计算一次。

开始播放后，视频按自身帧率前进并更新 Dashboard 数据。暂停保留当前帧和检测覆盖层；停止将视频暂停并回到待机状态，不清除标定、当前帧和已有 CASE；自然播放结束停留最后一帧。选择新视频会清空标定、趋势和 CASE。切换模块或组件卸载时取消帧回调并回收 Object URL。

## Dashboard 数据映射

检测结果通过独立 `LineProtrusionDataProvider` 和纯函数 mapper 转换为现有 `DashboardViewModel`：

- 媒体区域显示视频和光斑/基线覆盖层。
- 指标中的突出量显示两根导线绝对偏移的最大值，单位改为 `°`。
- 阈值显示当前报警阈值，事件等级映射正常、橙色预警和红色报警。
- 趋势图第一条序列保存最近的最大偏移，第二条序列显示报警阈值。
- 正常状态不创建 CASE；导线进入预警或报警时分别创建橙色或红色 CASE，点位包含导线编号。
- 解码、标定或追踪失败以可恢复提示显示，不隐藏三栏 Dashboard。

现有线夹目录批处理控制保持不变。`MediaPanel` 接收模块专用的可选控制模型；线夹继续显示目录控件，线突出显示视频和标定控件，其他模块继续显示原有媒体元数据。

## CASE 去重状态机

每根导线独立保存上一次状态。仅以下迁移创建 CASE：

- `ok → warning`
- `ok → alarm`
- `warning → alarm`

`warning → warning`、`alarm → alarm` 和 `alarm → warning` 不创建重复记录。恢复 `ok` 后，下一次进入异常状态可以重新创建 CASE。CASE 在当前视频会话内累积，表格使用现有内部滚动。

## 错误与资源管理

- 非视频文件、无法解码的视频或没有有效尺寸的视频显示双语错误提示。
- 标定失败只显示提示并保留视频和已有标定，允许重新拖线。
- 单帧追踪失败不终止视频；该帧标记失败，下一帧继续尝试。
- 新视频、切换模块和卸载时必须取消视频帧回调、暂停视频并回收旧 Object URL。

## 测试与验收

- 单元测试使用手工构造的灰度像素验证三光斑定位、`±50px` 追踪、偏移公式、阈值分类和总状态优先级。
- 状态机测试验证异常 CASE 只在规定的状态迁移生成。
- mapper 测试验证媒体、角度指标、趋势、覆盖层和中英文事件语义。
- 控制器测试验证开始、暂停、停止、自然结束和资源释放。
- 完整 `npm test`、`npm run build` 和 `git diff --check` 必须通过。
- Chrome 以参考 MP4 验证选择视频、两次标定、播放检测、阈值变化、CASE 累积、结束停留最后一帧及 1600×900 布局无溢出。
